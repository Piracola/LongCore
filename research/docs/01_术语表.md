# Windows 开发术语表（面向初学者）

按你在本项目会遇到的顺序解释每个术语。读完这篇，你就明白"逆向出硬件 API"到底是怎么一回事。

---

## 1. 硬件与固件层

### 固件 (Firmware)
烧录在主板芯片里的"小型操作系统"，电脑没开机它就在运行。本项目打交道的固件叫 **BIOS/UEFI**（蛟龙 16 Pro 的版本号是 `MRID6_23_V33`）。风扇转速、功耗上限这些底层开关，最终都是固件在执行。

### ACPI（高级配置与电源接口）
一个**行业标准协议**，定义了操作系统和固件之间的对话方式。Windows 想知道"CPU 多少度""风扇转多快"，不是直接戳硬件，而是按 ACPI 的规矩问固件。厂商可以在 ACPI 里自定义"扩展功能"（比如蛟龙的性能模式切换），这些扩展就叫 **ACPI 方法**。

### EC（嵌入式控制器，Embedded Controller）
主板上的一颗独立小芯片，专门管键盘灯、风扇转速、电池这些"杂活"。CPU 温度墙、风扇转速最终都由 EC 执行。**我们并不能直接访问 EC**——厂商把对 EC 的操作封装进了 ACPI 方法里，操作系统只能通过 WMI 调用这些方法。这就是"标准接口"的好处。

### WMI（Windows Management Instrumentation）
**Windows 的"设备信息总线"**。它是 Windows 自带的一个服务，任何程序都能用它查询系统信息（CPU 温度、电池状态）或调用设备驱动暴露的方法。蛟龙控制中心的全部硬件控制就是走 WMI。

你可以把它想象成"设备的客服热线"：拨通指定号码（命名空间+类名），报上指令（方法+参数），对面执行并回话。

### CIM / WMI 的关系
CIM 是 WMI 底层遵循的**国际标准模型**。微软新推的 PowerShell 命令 `Get-CimInstance` 就是用 CIM 协议访问同一个信息库。老命令 `Get-WmiObject` 做同样的事，但已弃用。本项目代码里两者等价。

### 命名空间 (Namespace)
WMI 信息的"分类目录"。常用的：
- `root\CIMV2` — 系统通用信息（CPU、内存、进程）
- `root\WMI` — **硬件厂商扩展区**，蛟龙的接口全在这里
- `root\StandardCimv2` — 网络等

### WMI 类 (Class)
命名空间下的"信息模板"。例如 `MICommonInterface` 就是蛟龙在 `root\WMI` 里注册的一个类，它声明"我提供一个方法叫 `MiInterface`，收 32 字节，返回若干字节"。

用 PowerShell 查看一个类的定义：
```powershell
Get-CimClass -Namespace root\WMI -ClassName MICommonInterface
```

### 实例 (Instance)
类是模板，实例是"具体的设备"。蛟龙的类只有一个实例，名叫 `ACPI\PNP0C14\MIFS_0`。
- `PNP0C14` 是 Windows 给"ACPI WMI 设备"分配的固定设备 ID
- `MIFS_0` 是厂商起的名字（MI = Mechanical Intel？不确定，F = Firmware，S = System 之类）
- 类比：类=「型号」，实例=「你这台具体的机器」

### GUID（全局唯一标识符）
128 位的随机 ID，用来在系统里唯一标记一个东西。每个 WMI 类都有一个 GUID（蛟龙的是 `{b60bfb48-3e5b-49e4-a0e9-8cffe1b3434b}`），Windows 靠它把 WMI 类和底层驱动对应起来。

### MOF（Managed Object Format）
描述 WMI 类的**定义文件格式**。驱动安装时把 .mof 文件交给 Windows，Windows 才"认识"这个类。这就是为什么类定义里有个 `dynamic` 限定符——表示"这个类是运行时动态提供的"。

### 方法调用 (InvokeMethod)
对 WMI 实例执行一个动作。蛟龙只有一个方法 `MiInterface`，但它是个"万能通道"：你传 32 字节进去，字节里编码了"真正的命令"（详见协议手册）。这种设计叫**透传协议**。

### 事件 (WMI Event)
WMI 不止能"问答"，还能"订阅推送"。蛟龙注册了事件类 `HID_EVENT20`：当你按 Fn 组合键，固件发事件，程序立即收到。这比轮询高效。

### HID（人机接口设备，Human Interface Device）
USB/键盘/触摸板这类输入设备的协议标准。`HID_EVENT20` 名字里的 HID 意味着这些事件源自键盘控制器。

## 2. CPU 与功耗术语

### P-state（性能状态）
CPU 的"档位"。P0 = 全速，P1 = 稍慢……数字越大越省电越慢。超频工具改的就是 P0 的频率上限。

### SPL / SPPT / 温度墙（ Stefan / Stapm 三个 AMD 术语）
AMD 笔记本 CPU 的三重功耗限制，蛟龙固件都支持自定义：
- **SPL**（Sustained Power Limit，长时功耗）：持续负载时的功耗上限。本机范围 75–85W
- **SPPT**（Short-term Power Limit，短时功耗）：爆发负载（如游戏加载）允许的短暂峰值。本机范围 105–120W
- **温度墙**（Temp Wall）：温度超过它就强制降频。本机实测 74–75°C

### 混合模式 vs 独显直连 (Hybrid / Discrete)
- **Hybrid**：游戏画面经过核显中转再输出到屏幕，省电但损失几帧
- **Discrete**：RTX 独显直连屏幕，性能最佳但切模式**必须重启**
- 代码枚举值：0 = Hybrid，1 = Discrete

## 3. 可执行文件与逆向术语

### PE 文件（Portable Executable）
Windows 可执行文件的标准格式（.exe / .dll / .sys 都是）。文件开头有 "DOS 头"（`MZ` 魔数）→ PE 头 → 节区（代码/数据/资源）。我们写的 `carve_pe.py` 就是解析这个格式来"雕刻"出文件的。

### 安装包打包器（Inno Setup / NSIS）
把一堆文件压成一个安装程序的软件。蛟龙用的是 **Inno Setup 6.3.0**。安装包 = 一个 PE 引导程序 + 一大坨压缩数据。我们的逆向路径：定位压缩数据 → 解压 LZMA → 按顺序切开 371 个 PE。

### LZMA
一种高压缩比算法（7-Zip 的核心）。安装包里的数据就是单条 LZMA1 裸流（89MB 压缩成 170MB 解压）。Python 的 `lzma` 模块可以直接解。

### 文件雕刻（File Carving）
 forensics 术语：不知道文件边界时，靠**特征串**（如 PE 的 DOS stub 文本 "This program cannot be run in DOS mode"）判断每个文件的起点和终点。我们从 170MB 数据流里雕出了 371 个完整文件。

### .NET / CLR / CIL
微软的开发平台。蛟龙主程序是 **.NET 6 WPF** 应用。.NET 程序编译成**中间语言 (CIL)** 而非机器码，所以能被 ILSpy **反编译回接近原始的 C# 源码**——这是本项目最大的突破口。原生 C++ 程序反编译出来是汇编，难度高一个数量级。

### apphost
`.dll` 里看到的"蛟龙游戏控制中心.dll"其实是个**启动器**（apphost）：它自己不含逻辑，只负责启动真正的 .NET 程序集。这也是为什么我们一开始认错了核心文件。

### 反编译 (Decompilation)
把二进制还原成高级语言源码。工具：ILSpy（本项目用的 `ilspycmd`）。产物在 `decompiled/main.cs`（5150 行）。

### WPF（Windows Presentation Foundation）
微软的桌面 UI 框架（XAML + C#）。蛟龙控制中心界面就是 WPF 写的。

### P/Invoke
.NET 调用**原生 C/C++ DLL** 的机制。蛟龙调用 KaronOC.dll 就靠它：
```csharp
[DllImport("KaronOC.dll", CallingConvention = CallingConvention.Cdecl)]
private static extern int ChangePstatesLevel0Settings(int grClockOffset, int memClockOffset);
```
`CallingConvention.Cdecl` 是函数参数入栈顺序的约定，调错了会栈错乱。

### NVAPI / NvAPIWrapper
NVIDIA 官方的 GPU 控制 API（私有的）。改 GPU 频率、读 GPU 温度都用它。`NvAPIWrapper.dll` 是开源社区对它的 .NET 封装。KaronOC.dll 内部也是走 NVAPI。

### PowerShell
Windows 官方脚本语言（基于 .NET）。本项目用它做 WMI 实测——不需要写 C#、编译、签名，一行 `Invoke-CimMethod` 就能发命令。

### 管理对象 (ManagementObject) 与 GetMethodParameters
.NET 的 `System.Management` 命名空间提供的 WMI 客户端对象。调用方法的固定三步：
```csharp
var mo = new ManagementObject("root\\WMI", "MICommonInterface.InstanceName='ACPI\\PNP0C14\\MIFS_0'", null);
var prm = mo.GetMethodParameters("MiInterface");  // 1. 拿参数模板
prm["InData"] = myBytes;                          // 2. 填参数
var out = mo.InvokeMethod("MiInterface", prm, null); // 3. 执行
```

## 4. Git 与工程术语

### Git / 仓库 (Repository)
版本记录系统。"仓库"就是一个被 Git 追踪的文件夹，每次提交（commit）存一个快照，随时可回退。

### .gitignore
告诉 Git "这些文件别管"。本项目用它排除厂商二进制（`installed/`、`extract/`）——**这些文件有版权，进了仓库就不能开源**。

### commit
一次快照记录，附说明文字。好的习惯：每个功能节点提交一次，说明写清"做了什么、为什么"。
