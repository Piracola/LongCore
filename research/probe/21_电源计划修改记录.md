# 21 · 电源计划修改记录（最小处理器状态）

> 日期 2026-09-30　执行人：DSH（经用户明确指示）
> 起因：全系统卡顿掉帧排查。详见下方实测数据。

## 改了什么

`PROCTHROTTLEMIN`（最小处理器状态）在**三个电源方案里全部被设为 80%**，
导致 CPU 空闲时也不低于 80% 性能档 —— 空闲功耗 45-49W、Tctl 83-85℃。

已改为 **AC=5% / DC=5%**，覆盖全部三个方案。

| 方案 | GUID | 改前 AC | 改前 DC | 改后 AC | 改后 DC |
|---|---|---|---|---|---|
| 平衡 | `381b4222-f694-41f0-9685-ff5bb260df2e` | 80% | 5% | **5%** | 5% |
| 省电 | `3f89a038-2a9d-4fd1-9491-e4e7ebe9cc25` | 80% | 5% | **5%** | 5% |
| HYDRA | `ae45605e-d8e5-4b6d-b5c5-bdc5fbba97c8` | 80% | 5% | **5%** | 5% |

## 执行的命令

```powershell
$SUB='54533251-82be-4824-96c1-47b60b740d00'   # SUB_PROCESSOR
foreach ($g in '381b4222-f694-41f0-9685-ff5bb260df2e',
               '3f89a038-2a9d-4fd1-9491-e4e7ebe9cc25',
               'ae45605e-d8e5-4b6d-b5c5-bdc5fbba97c8') {
  powercfg /setacvalueindex $g $SUB PROCTHROTTLEMIN 5
  powercfg /setdcvalueindex $g $SUB PROCTHROTTLEMIN 5
}
powercfg /setactive SCHEME_CURRENT
```

## 回滚（恢复原值）

```powershell
$SUB='54533251-82be-4824-96c1-47b60b740d00'
foreach ($g in '381b4222-f694-41f0-9685-ff5bb260df2e',
               '3f89a038-2a9d-4fd1-9491-e4e7ebe9cc25',
               'ae45605e-d8e5-4b6d-b5c5-bdc5fbba97c8') {
  powercfg /setacvalueindex $g $SUB PROCTHROTTLEMIN 80
  powercfg /setdcvalueindex $g $SUB PROCTHROTTLEMIN 5
}
powercfg /setactive SCHEME_CURRENT
```

## 实测效果

| 指标 | 改前 | 改后 |
|---|---|---|
| 包功耗（轻载） | 45-49 W | **39.7-43.6 W** |
| Tctl | 83-85 ℃ | **76-81 ℃** |
| 有效频率最低值 | 222 MHz | **8-10 MHz**（真正深度降频） |
| CPU 风扇 | 3477 RPM | 3472-3489 RPM |

改善约 **5-7℃ / 5-7W**。仍偏高，说明还有其它因素（见下）。

## 与 LongCore 的关系：不冲突

LongCore 的「性能模式」是 **EC 固件档位**（写 EC 命令 8 `SystemPerMode`），
与 Windows 电源计划是两个独立层：

| 层 | LongCore 的操作 | 触碰 PROCTHROTTLEMIN |
|---|---|---|
| EC 固件档位 | `MethodServices.SetValue(SystemPerMode, mode)` | 否 |
| 电源计划·切换方案 | `PowerPlanHelper` 只做 `powercfg /setactive {guid}` | 否 |
| 电源计划·内部参数 | `PowerController` 只写 `PROCFREQMAX`、`PERFBOOSTMODE` | 否 |

且 `App.SyncWindowsPowerPlan` 在 `config.yaml` 中为 **false**，联动当前未启用。

## 遗留项（未处理）

1. **`PROCFREQMAX` = 4800 MHz**（平衡方案 AC/DC）。Windows 默认 0（不限）。
   这是 LHM「最高核频」恒为 4766 MHz 的原因。注意与 LongCore 配置的
   `CpuMaxFrequency: 5000` 对不上，疑为其它工具所设。
   各方案不同：平衡 4800/4800、省电 0/4500、HYDRA 4500/4500。
2. **`HYDRA` 电源方案**（`ae45605e-…`）—— 疑为 Project Hydra（锐龙调优工具）建立。
   注册表里只有它显式写了 80%。当前无 Hydra 进程在运行。
3. **3 个虚拟显示适配器**（MuMu / GameViewer / OrayIdd）—— 掉帧的可疑来源，未处理。
4. 轻载功耗仍有约 41W 且 Tctl 78-81℃。台面背景负载不低（Chrome 两进程约 122% 单核、
   dwm 24%、System 27%），测得值含这些负载；纯空闲数值未单独测。
5. 物理散热：45W 时风扇 3500 RPM 仍有较高温度，清灰/硅脂未验证。

## 若 80% 被写回

若重启或运行某些工具后 80% 复现，说明有程序在写。排查方向：
计划任务、服务、以及 OEM 控制中心/调优工具。可用下面的命令定期核对：

```powershell
powercfg /query SCHEME_CURRENT SUB_PROCESSOR PROCTHROTTLEMIN
```
