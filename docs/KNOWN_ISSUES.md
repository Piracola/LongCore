# 已知问题清单（Known Issues）

> 版本：LongCore 0.1.0 · 2026-09 · 持续更新

## 行为限制（设计如此 / 有意取舍）

1. **浏览器直连预览显示全 0**
   通过普通浏览器访问前端页面时没有 WebView2 桥（`window.chrome.webview` 缺失），
   温度/转速/功耗等数据全部为 0。这是预期行为——完整功能必须在主窗口内使用。

2. **飞行模式（AirPlaneMode）不提供热切换**
   EC 命令 9（显卡模式）写入后必须重启生效，不能作为"模式热切换"处理。
   独显/混合切换保留在设置页（GPUDirectConnection），切换后请手动重启。

3. **"自定义"性能模式是本地逻辑态**
   自定义档（第 4 段胶囊）不写入 EC 模式命令，仅打开命令 23 的自定义功耗子状态；
   实际 SPL/SPPT 数值以 CPU 页保存的配置为准。切回标准档时自动关闭该子状态。

4. **Fn 热键只接管性能模式键（事件 15）**
   其余 Fn 复合键（亮度/触摸板/灯效等）保持固件默认行为，LongCore 不拦截。
   可在设置页整体关闭接管（`App.HotkeyEnabled`）。

5. **应用内曲线接管会绕开 EC 固件温控（有意取舍）**
   固件三档（办公 / 游戏 / 狂飙）下 EC 自带温控表在低负载区把转速压得极低、临近温度墙
   （默认 95℃）才跳变，表现为"平时很静、到墙才猛拉"，其形状无法从软件层改变。
   因此应用内曲线接管在三档下同样生效（`Fan.Enabled`）。代价是写入转速会置位 `0xB20`
   手动掩码，EC 自身温控被绕开，软件成为唯一控制者；兜底为 `ThermalWatchdog`（默认 98℃
   持续 10s 强制 5800 RPM）与 `EcGuard`（进程崩溃后下次启动恢复 EC 自动模式），二者默认开启。
   关掉曲线开关或应用手动转速即交还 EC。

6. **曲线接管会产生"转速抖动"，0.1.4 改为温度域抑制**
   实测（2026-09-23，28.5 分钟真实负载）：CPU 风扇**没有一秒是停着的**——88 个采样点
   全部各不相同，102 次方向反转中 95 次幅度只有 100 RPM（每 1~2 秒就改写一次硬件）。

   0.1.3 曾在最终 RPM 上加 300 RPM 死区，**实测无效**，三点原因（均由真机日志
   21:02~21:32 的 1789 个 1 秒样本离线重放确认）：
   - 旧"非对称低通"本身就是噪声放大器。系数 0.25/0.12 的时间常数只有 3~7 秒，而温度计
     每秒抖动 ±2℃（|dT| 均值 0.71℃/s、p99 = 5℃/s —— 这个量级的变化在热质量面前不可能是
     真实温度），于是平滑值摆幅约 ±3℃，比原始读数更大。
   - 死区在转速域：挡得住 100 RPM 的量子抖动，挡不住"被放大后的 ±3℃ × 曲线斜率" = ±400 RPM。
   - 升降斜坡对称（各 600 RPM/s），降温方向同样激进。

   0.1.4 改为三件事（详见 `AutoFanControl.ProcessAndApplyFanSpeed`）：双跟踪器
   （`TempAttackS`=10s 快升 / `TempReleaseS`=60s 慢降，转速一律由慢跟踪器查曲线）、
   温度域不灵敏带（`TempHysteresisC`=5℃）、降速每秒最多退一格。
   同一段真实数据离线重放：写入 **88 → 3 次**、方向反转 **36 → 0 次**（30 分钟窗口），
   跟踪值与真值的均值偏差仅 +0.15℃。代价是转速对温度的跟随整体变钝（最多滞后
   一个不灵敏带宽度），因此 90℃ 以上急停段与 98℃/10s 看门狗成为主要的过温兜底。

   同时移除了 CPU→GPU 的 0.85 交叉同步：实测 GPU 仅 56℃ 时其风扇被 CPU 拖到
   3400 RPM（按自身曲线只需 1500~1800），那是零散热收益的噪音源。

7. **日志默认不再记录逐次数据读取**
   旧行为是每次 WMI/EC 读取、每次前端 IPC 调用都写一行 DEBUG，实测一天 5.7 万行
   / 6.4 MB（约 27 次/秒同步写盘），其中 98.4% 出自 `CommandResult` 构造函数。
   现默认 `Log.Level=INFO` 且 `Log.CommandDebug=false`，控制侧信息
   （AutoFanControl 转速、看门狗、EcGuard、写入闸门拦截）一行不少。
   排查读取类问题时可临时打开；三项设置均在设置页，改后立即生效无需重启。

8. **OSD 需要 UI 线程可用**
   Fn 切换模式的屏幕提示经 WPF Dispatcher 显示；若主窗口线程被长时间阻塞，
   提示会延迟出现。窗口最小化到托盘时 OSD 仍可正常弹出。

9. **SMU 限制值不可回读，「重置」不等于「恢复系统默认」**
   12 项 SMU 限制参数没有可靠 getter（只能确认命令是否被接受），界面因此显示「未读取」
   而不是 0，0 也会被前后两道写入闸门拒绝。由此：SMU 页只对**有明确默认值**的参数提供重置
   —— 曲线偏移=0（不偏移）、逐核 CO/OC=0；温度墙的 99℃ 是**应用推荐值**（页内已如此标注），
   不是固件读回值。功耗/电流限制**不提供重置**：官方控制台没有这些参数的 API 与数值
   （反编译 vendor/decompiled 零命中），配置模型里它们的默认值就是 0（=未读取），
   编一个数字写进固件就是虚假成功。见 v4 §14.4。

## 平台 / 环境相关

9. **必须管理员权限运行**
   EC 驱动加载、WMI 写入、`powercfg` 联动均需要管理员。安装器已配置
   `requireAdministrator`；若直接运行 exe 被拒，请右键"以管理员身份运行"。

10. **WMI 通道抖动**
   响应校验失败会自动重试一次（连续两次失败判定为通道异常并返回默认值）。
   休眠唤醒后首几次读取可能短暂失败，随后自愈；若持续失败请重启应用。

11. **GPU 温度来源依赖 NVAPI**
   NVIDIA 驱动不可用或初始化失败时，GPU 温度沿用该风扇上一次的平滑值，
   **不再回退成 CPU 温度**（2026-09-23 改）。原先的回退会把单调 80~86℃ 的 CPU 温度
   灌给只接一路 GPU 的风扇，与"各自跟随自己温度"的设计相互抵消。
   实测日志中该分支从未触发。

12. **无噪音传感器**
   首页噪音值按风扇转速查表估算（3000 RPM≈25 dBA 标定），仅供参考。

## 版本历史修复（上游问题，本 fork 已解决）

13. **性能模式枚举错位**（上游遗留）：前端 TS 枚举顺序与后端 C# 枚举不一致，
    上游靠页面"错位命名"掩盖。0.1.0 起前后端枚举已对齐（Balance=0 / Performance=1 /
    Quiet=2 / Custom=3）。

14. **EC 高频重复写入**（上游遗留）：自动风扇控制环曾以固定 1s 周期无条件重写 EC。
    现已加入同地址同值 300ms 去重节流与写入地址白名单。

15. **崩溃后风扇状态残留**（上游遗留）：进程硬崩溃时手动风扇模式可能残留在 EC 中。
    现已加入心跳护栏，下次启动检测到过期心跳会自动恢复风扇自动模式。

## 尚未验证

16. **电池（DC）供电场景**：AC/DC 双参数切换在电池下未做长时间实测。
17. **Windows 10**：开发与测试均在 Windows 11 24H2；Win10 22H2 理论可用（WebView2 可
    通过安装器离线包安装），未实测。
18. **多字节 RGB 键盘灯效**：灯效命令（16/17/18）沿用上游实现，未在 0.1.0 重新验证。
19. **0.1.4 的风扇改动全部基于离线重放，未做实机验收**：双跟踪器、温度域不灵敏带、
    降速限幅，均以 2026-09-23 实机日志（28.5 分钟真实负载、1789 个 1 秒温度样本、
    366 次转速写入）离线重放得出。重放能证明"写入次数大幅下降"，但**最后一步只能靠耳朵**；
    且重放把温度当作与转速无关的外部输入，闭环下的实际温度摆幅会略大于重放结果
    （风扇变慢 → 温度升高 → 触发下一次升速，是自纠正的）。
    若仍有可感知的"呼吸感"，下一手是把 `TempHysteresisC` 从 5℃ 提到 8℃。
20. **0.1.3 的两项转速参数在 0.1.4 被删除**：`TempSmoothRisePercent` /
    `TempSmoothFallPercent` / `FanSpeedDeadbandRpm` / `MaxRamp*RpmPerSec` 已不再存在，
    升级后首次落盘会从 `config.yaml` 中消失（旧文件里的这些键被静默忽略）。
    新出厂曲线仍未在本机生效，除非显式处理：`ConfigSerializer.Update()` 是无损迁移，
    升级会保留已有的 `CpuFanCurve`/`GpuFanCurve`，只补上新字段的默认值。

21. **模式切换的失败路径未做真机演练**：切档被拒 / 命令被接受但回读未确认，会弹错误消息并在
    该档位显示 3 秒错误态（Home.vue），但这条路径只在 mock 桥接下出过图，没在真机上制造过
    一次真实失败。验证方法：管理员运行后在首页连点档位，或临时禁用 EC 驱动后切档。
22. **SMU 限制值回读未实现**：RyzenSmuControllerTest 的 --smu-read <hex> 已能读任意 SMU 寄存器，
    但要把它对应到「STAPM/PPT/TDC/EDC/温度墙」需要 SMU 传输表协议（本仓无该常量，ryzenadj 用的是
    同一 mailbox 的另一组命令），且必须按 family（FP6/FP7/Strix/AM5）逐一真机验证。完成前，
    SMU 页的「未读取」是**诚实**的，不要用软件记录值冒充硬件真值。
