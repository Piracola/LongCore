## 1. 为什么要做（Observation，均带 `文件:行`）

**O1 · 各页「重置」语义不一致（本轮直接动因）**

- `JiaoLongControl/Client/src/pages/CPU.vue:184-194` —— 重置只 `Object.assign(CPUData.Custom, CPU_CUSTOM_DEFAULTS)` + `saveConfig()`，**不下发硬件**（注释自己写着「只改参数并存盘，不下发硬件」）。
- `JiaoLongControl/Client/src/pages/RyzenSmu.vue:363-372` —— 同上：只填表单 + 存配置，注释「重置 = 只改表单值并写回配置，不下发硬件」。
- `JiaoLongControl/Client/src/composables/useFanCurveEditor.ts:399-466` —— 曲线页「交还 EC 固件温控」走 `handleHandoffToEc()`，**真下发**（停曲线 + `Fan.RemoveFanSpeed` + 落盘 `Fan.Enabled=false`）。2026-10-06 前这是已删除的 `src/pages/Fan.vue:119-126` 上的「重置」。
- `JiaoLongControl/Client/src/pages/GPU.vue:308-337` —— 重置调 `NvidiaGpu.ResetGpuClock()` / `ResetMemoryClock()`，**真下发**。

同一个词在三个页面上有两种含义，用户无法从界面判断「点了重置之后，硬件到底变没变」。

**O2 · 可逆性分级此前只是日志标签**

`src/domain/operations.ts:21-29` 定义了 a–e 五级可逆性，硬规则写着「只有 level === 'a' 才允许 UI 出现『回滚/撤销』字样」。
但全仓 `reversible: 'x'` 共 26 处（`src/` 内 22 处，另 4 处在 `src/domain/__tests__/operations.spec.ts`），**全部只写进活动日志**：

- `src/domain/cpuPowerPlan.ts:31`、`src/stores/mode.ts:217/232/254/287/298`、`src/stores/fan.ts:203/219/231`、
  `src/pages/CPU.vue:158`、`src/pages/GPU.vue:262/303`、`src/pages/RyzenSmu.vue:225/280/327/355`、
  `src/composables/useFanCurveEditor.ts:135/147/404/463`

没有任何一处用它约束按钮。本轮把它变成真门禁：`src/domain/appliedFeatures.ts` 的 `removalBlockedReason()`。

**O3 · 前端配置类型缺 `Safety` 段**

- 后端模型有：`JiaoLongControl/Server/Core/Models/JiaoLongConfig.cs:13`（`Safety` 属性）与 `:22-45`（`SafetySection`：`WriteGateEnabled` / `ThermalWatchdogEnabled` / 四项看门狗阈值）。
- 前端类型没有：`JiaoLongControl/Client/src/types/config.ts:98-106` 只声明 `App/Cpu/Gpu/Fan/Log/Smu`。
- 设置页因此只能用字符串路径访问：`src/pages/Settings.vue:54-59` 传 `configPath: 'Safety.ThermalWatchdogEnabled'`，由 `src/components/common/SettingToggle.vue:43-50` 动态按路径取值（`:52` 兜底 `?? false`）。

运行时该字段确实在桥接返回的 JSON 里，所以开关值是对的；但**类型层面没有契约**——后端新增字段时前端不会报错，只能靠人记得同步。本看板直接从桥接 JSON 按路径取值（`readByPath`），不受这个类型缺口影响。

**O4 · 桥接「类型声明」与「运行时可调用面」不一致**

`src/utils/bridge.ts` 的 `BridgeApi` 是**类型声明**，真正导出给页面用的是同文件下方的包装对象（行号已随 2026-10-06 的键盘功能删除而变动，故只给文件不给行号）：

| 声明里存在 | 包装对象里不存在 | 证据 |
|---|---|---|
| `Fan.SetMaxFanSpeedSwitch` / `GetMaxFanSpeedSwitch` | `Fan` 导出对象只有 `GetFanSpeed` / `RemoveFanSpeed`（`SetFanSpeed` 包装随「风扇手动设定风速档位」于 2026-10-06 删除） | 声明 `src/utils/bridge.ts:168-169`，导出 `:459-462` |
| `RyzenSmu.SetTdcLimitMp1` / `SetTdcLimitRsmu` | `RyzenSmu` 导出对象无这两个方法 | 声明 `src/utils/bridge.ts:276-277`，导出 `:614-639` |

即：类型上「存在」、运行时调用会抛。本轮的注册表用例把这条做成了判别性反例（`resolveBridgeMethod(bridge, 'Fan.SetMaxFanSpeedSwitch') === null`），防止以后再出现「照类型抄一份名单」。

**O5 · 三个功能/字段在前端没有任何消费点**

- TDC 电流限制：配置模型有字段（`Server/Core/Models/JiaoLongConfig.cs:300-303`）、类型有声明（`bridge.ts:276-277`）、页面 `CONFIG_GROUPS` 没有（`src/pages/RyzenSmu.vue:40-97`）、包装对象也没有写方法（`bridge.ts:614-639`）。
- GPU 高级超频面板：整段被注释（`src/pages/GPU.vue:501-624`，含 `handleApplyAdvanced`/`handleResetAdvanced` 的按钮），写方法只剩声明（`bridge.ts:239-241`、`:579-582`）。

本轮所有「配置开着·硬件没写进去」都是假状态驱动出来的（mock 桥 + 单测），**没有一次真机复现**。

## 5.1 复查整改（2026-10-05，独立审查后的 FIX-1~6）

**D5 · 「硬件当前是否真的生效」升为一等字段，「全部还原」按它判定**（负责人：实施者（AI，复查整改），2026-10-05）

依据（Observation，可复现）：旧实现 `bulkRemovalPlan()` 用 `status` 白名单
（`['match','mismatch','hardware-only','no-write-path']`）反推"是否还生效"，而 `judgeFeature` 在
`unreadable / read-failed / intent-missing / no-write-path / observed-only` 这些返回路径上**不输出这个信息**，
于是两头都错：漏掉 `observed-only`（5 项实测正开着：`cpu.custom-override`、`keyboard.color`、`keyboard.brightness`、
`keyboard.logo-light`、`system.autostart`），又无条件收 `no-write-path`（`gpu.core-offset`/`gpu.memory-offset`/`gpu.voltage-boost`
—— 注册表自己写着"硬件侧的值非本软件所写"，点一下会执行 `ResetClockOffsets()`/`SetVoltageBoostPercent(0)`，
清掉别的工具设的偏移）。

做法：
- `FeatureVerdict` 增一等字段 `observedActive: boolean | null` —— `readback === null` 或回读非 `ok/stale` → `null`（不知道），
  否则 `evalRule(observedRule, picked)`；
- `bulkRemovalPlan()` 三条同时满足才收：`canRemove === true` **且** `writePath !== null` **且**
  （`observedActive === true` **或**（`observedActive === null` **且** 配置意图明确为开，保留"一次读取失败不该卡住用户"的口径））；
- 新增 `removalScope()`（纯函数）把覆盖范围算成数据：「覆盖 / 非本软件下发 / 当前未生效 / 没读出生效值 / 本行不给移除」，
  界面按钮 `title` + `aria-label` + 一行说明**逐项列出**，不再只报一个数字。

复现（实测，非推断）：任务书 FIX-1 命令修前输出 `[]`（漏 `cpu.custom-override`）、修后输出 `[ 'cpu.custom-override' ]`

这正是新增用例 ③（`writePath === null` 的项无论实测真假都不进计划）要钉住的场景。
