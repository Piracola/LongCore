# 技术栈与 UX 审查结论（2026-09-11）

本文记录一次苏格拉底式问诊的结论：LongCore 在功能已基本对齐官方控制台之后，下一步的投入方向与技术栈取舍。

---

## 1. 问题演化

| 阶段 | 用户表述 | 性质 |
|---|---|---|
| 初始问题 | "如何进一步改进项目，使其完全取代官方控制台，并拥有优美高效的 UX 与强大功能" | 目标，但"取代"未定义 |
| 澄清 1 | 目标是对**所有蛟龙16 Pro 用户**的完整替代品，而非个人够用 | 设定了标尺 |
| 澄清 2 | 改口：官方控制台功能已**几乎全覆盖**；fork 初衷是 UX/UI/动效/仪表盘 | 问题从"缺什么"转向"品质" |
| 澄清 3 | 换栈欲望源于**抽象判断**（"2026 年是否过时"），非具体痛点 | 关键：非痛点驱动 |
| 澄清 4 | 明确**愿意放弃上游 rebase、彻底独立发展** | 移除换栈最大反对理由 |
| 澄清 5 | 可感知目标：流畅原生 UI、小体积（7.4MB 已满意）、全新仪表盘动效、性能状态联动外观、运行日志、去"AI 味" | 具体收益清单 |
| 澄清 6 | 希望**尽量**做到 Win11 原生视觉，工作量大则**非必须** | 原生视觉是软约束 |

最终收敛为可行动的问题：**在不更换核心技术栈（WPF + WebView2 + Vue3）的前提下，LongCore 的界面视觉与动效能做到多接近 Windows 11 Fluent Design 原生水准？**

---

## 2. 核心判断

**栈不动。** 现有 WPF + WebView2 + Vue3 可达 Fluent 原生水准的约 **85%**，且恰好覆盖用户列出的全部可感知目标。换 WinUI3 只为最后 15 分差异，代价是全量 UI 重写 + 放弃 Vue/ECharts 生态 + 安装包 7.4MB → 30MB+（WinAppSDK 运行时）+ 单人迭代速度腰斩。

**决定性技术事实**：Mica 不是 WinUI3 专利，它是 **DWM 的窗口属性**。任何 HWND（含 WPF 窗口）调用
`DwmSetWindowAttribute(hwnd, DWMWA_SYSTEMBACKDROP_TYPE, 2 /*DWMSBT_MAINWINDOW*/)` 即可获得与系统设置应用**完全相同**的真·Mica；配合 WebView2 透明背景，前端内容直接叠加在 Mica 之上。

---

## 3. 代码核查事实（证据）

- `JiaoLongControl/Server/MainWindow.xaml`：`WindowStyle=None` + `GlassFrameThickness=-1`，**无任何 DWM backdrop 调用**，无系统强调色跟随 → 距真·Mica 约 30 行 C#
- `Client/src/assets/Global.scss`：令牌体系已较完善（圆角/字阶/温度色阶/Arco 联动），但**风格是 AI 着陆页方言**：
  - 紫罗兰辉光 `--color-accent-purple: #8a2be2` + `box-shadow: 0 0 20px`
  - 大圆角 `--radius-lg:16px / xl:20px / 卡片 24px`（Win11 标准为 8px）
  - hover 上浮 `translateY(-2px)` + 发光边框
  - 类名 `.glowing-card` / `.cyber-button` / `.active-glow`
  - 背景蓝紫渐变光晕 `--glow-blue` / `--glow-purple` / `--glow-center`
- 页面结构：`pages/{Home,CPU,GPU,Fan,RyzenSmu,KeyBoard,Settings,Main}.vue`，仪表盘在 `Home.vue` + `Home/{CoreMonitoring,StatusBar}`
- Arco Design 已通过 `body[arco-theme='dark']` 做品牌化覆盖，说明主题化管道已通

### 逐项差距清单（现状 → 现有栈内可达 → 代价）

| Fluent 要素 | 现状 | 栈内可达 | 代价 |
|---|---|---|---|
| Mica / 亚克力窗口材质 | 无，前端自画渐变 | **真·Mica**（DWM 调用 + WebView2 透明背景） | 约 30 行 C# |
| 圆角规范 | 16/20/24px | 8px（overlay 4/8） | 改令牌 |
| 动效曲线 | Material 0.3s `cubic-bezier(.4,0,.2,1)` + 发光 | Fluent 标准曲线 + 150/250/500ms 档位；Chromium 合成器 60fps 无压力 | 定义令牌并替换 |
| 字体排印 | 自定字阶 | 系统自带 **Segoe UI Variable**，对齐 Fluent Type Ramp | 改令牌 |
| 系统强调色跟随 | 固定品牌紫 | DwmGetColorizationColor / 注册表可读 | 小 |
| 系统控件微交互 | Arco 默认 | CSS 可模仿至肉眼难辨 | 中 |
| 暗色模式 | 已有完整双主题令牌 | 已达成 | — |

### 只有 WinUI3 能给的部分

仅剩系统控件微交互细节与深度系统集成，肉眼差异极小。账单：Vue+ECharts+Tailwind 全部推倒重来、体积膨胀、迭代变慢——**而用户已声明原生视觉"非必须"**，账不成立。

### 用户四个目标与栈无关

| 目标 | 实现路径 |
|---|---|
| 全新仪表盘动效 | Vue + ECharts + 编排动效，纯前端工程 |
| 性能状态联动外观 | 已是令牌化架构，body 上切 `data-perf` 属性即可联动全套变量 |
| 运行日志 | 后端 ring buffer + 落盘 + 前端图表页 |
| 去"AI 味" | 设计问题：克制、材质、层级、**零辉光** |

---

## 4. 行动建议（按依赖排序，P1 见效最快）

### P1 — 外壳原生化（建议先做，几天）
1. `MainWindow.xaml.cs` 调 `DwmSetWindowAttribute` 开 Mica；回退策略：Win10 用 Acrylic 或纯色
2. WebView2 `DefaultBackgroundColor` 设透明，前端 `html/body` 背景透明
3. 系统强调色读取与跟随（替换固定品牌紫）
4. `TitleBar.vue` 对齐 Win11 标题栏（caption 按钮尺寸 46×32、hover 背景、拖拽区）
5. **验证**：改造前后并排截图对比（这是唯一能终结"抽象焦虑"的实测数据）

### P0 — 设计系统重塑（1–2 周）
1. 新建 Fluent 对齐令牌：圆角 8px、Type Ramp、elevation 阴影替代辉光、Fluent 动效曲线
2. 全局清除 `.glowing-card` / `.cyber-button` / `.active-glow` 及所有 `box-shadow` 辉光
3. 移除背景渐变光晕，改用 Mica + 层级卡片
4. 建立"去 AI 味"自检清单：禁发光、禁大圆角、禁 hover 上浮、禁紫罗兰主色

### P2 — 仪表盘重做（2–3 周）
1. 先定信息架构（哪些数据值得常驻、哪些下钻），再谈动效编排
2. 可视化收敛为克制的图表语言，动效服务于状态变化而非装饰

### P3 — 状态联动外观 + 运行日志（2–3 周）
1. `data-perf` 属性驱动整套外观令牌（平衡/性能/静音/自定义）
2. 后端日志：ring buffer + 落盘 + 前端日志分析页

### P4 — 保险阀
P0–P3 完成后若仍不满足，再评估 WinUI3。届时手里是实测数据，而非"2026 年焦虑"。

---

## 5. 待验证假设（未实测，勿当作结论）

- "功能几乎全覆盖官方控制台"——未经逐项对照清单验证（可能存在意想不到的缺口）
- 现有 WebView2 前端的动效天花板——未实测帧率
- "AI 味"的具体构成——已从代码举证，但主观接受度未做用户验证
- 换栈工作量与收益——未量化（结论基于"非痛点驱动"这一判据，已足够定案）

---

## 6. 决策记录

- **2026-09-11**：用户确认放弃上游 rebase、彻底独立发展（原"每两个上游 release rebase 一次"策略作废，已同步至项目长期备忘）
- **2026-09-11**：定案不更换技术栈；以 P1 外壳原生化为首个落地动作
