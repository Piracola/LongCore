## 2. P0 卡死事故：已修复并复测 ✅（2026-09-17 闭合）

**现象**：切到 Ryzen SMU 后点击无响应，但界面数据仍在刷新；同期整个桌面（含资源管理器）一度无响应。**重启后不复现。**

### 2.1 已确证的机制（代码级）

「重启后不复现」本身是线索——它把嫌疑从"确定性 bug"推向**累积型竞态**：

    onMounted(async () => {             ← 回调是 async
      await CPU.GetPhysicalCoreCount()     ┐ 两次桥接往返
      await CPU.GetCpuInfo()               ┘
      pollingTimer = setInterval(...)    ← 定时器在这里才创建
    })
    onUnmounted(() => { if (pollingTimer) clearInterval(pollingTimer) })
                                    ↑ 此刻 pollingTimer 仍是 null，什么也没清

在两次 `await` 期间切走页面 → 定时器在**卸载之后**才创建 → **永久泄漏**。
Vue 是 SPA，切页不刷新文档 → 泄漏**在整个应用生命周期内累积**：每访问一次该页多一个 3 秒轮询器，
每个都对着 WPF UI 线程发一次真实 IPC（`cached` TTL 1s < 轮询 3s，缓存永不命中）。
→ 访问越多，UI 线程越饱和 → 输入先死、渲染进程独立故画面仍刷新 → 重启归零 → **不复现**。

放大器：`call()` **完全没有超时**、`cached()` **没有在途去重** → 宿主一变慢，请求排队**上界无穷**且永不自愈。

### 2.2 已落地的修复

| 文件 | 改动 |
|---|---|
| `bridge.ts` | `call()` 加 8s 超时；`cached()` 加在途去重 + 失败冷却(15s) + 仅成功写缓存；修 `ts` 取值时机 |
| `RyzenSmu.vue` | `telemetryInFlight` 在途守卫；`disposed` 标志根治泄漏；连续失败 5 次停轮询；不可见时停轮询；轮询先于 CPU 信息启动 |

### 2.3 顺带抓到的两个真缺陷

1. **13 个「应用」按钮的禁用态从未生效**：模板读 `loadingMap[item.key]`，写入却落在 `loadingMap['Set'+item.key]`——键名从不同名，防连点保护一直是假的，连点即连发写入。已用 `setterKey()` 对齐。
2. **0 值可直写固件**：截图里限制值全为 0（读取失败被渲染成合法值），13 个按钮全可点。已加前端硬闸门 `ZERO_UNWRITABLE`（12 个限制型 setter）：值为 0 时拒绝写入并说明理由，界面显示「未读取」且按钮置灰；豁免 `CurveOptimizerAll`（0 = 不偏移，合法）。**Server 侧闸门是第二道，属 Phase 2。**

### 2.4 验证证据与边界

| 检查 | 结果 |
|---|---|
| `vue-tsc --build` | ✅ 退出码 0（中途真抓到 `toJson()` 声明类型与运行时不符） |
| `eslint` 两文件 | ✅ 退出码 0 |
| `npm run build` | ✅ 在用户终端跑通（本会话沙箱 `spawn EPERM`，与源码无关） |

## 4. 结构层重推导：从硬件分类法 → 意图分类法

### 4.1 当前 IA 的根因

`Home / CPU / GPU / Fan / KeyBoard / RyzenSmu` 是 **WMI 协议的分类法**，即驱动作者的脑内结构，不是用户的。用户不会想"我要调 CPU"，用户会说：

| 用户的原话 | 真实意图 | 今天的路径 | 目标路径 |
|---|---|---|---|
| "太吵了" | 降噪 | 需先猜是 Fan / CPU / GPU 哪一页 | **1 击** |
| "烫了 / 降频了" | 热状态 | CPU + GPU 两页拼 | **1 击** |
| "这游戏帧数不够" | 性能最大化 | GPU + SMU + 模式三处 | **1 击** |
| "拔电要撑久点" | 能效 | 设置里翻电源计划 | **1 击** |
| "键盘太花" | 灯效 | KeyBoard 页 | **1 击** |
| "我刚才到底改了什么" | 审计 | **无此功能** | **1 击** |

### 4.2 推导出的导航

```
┌ 常驻主控轴：模式（静音 · 平衡 · 性能 · 自定义）+ 实时 温度/功耗/噪声 ─────┐
├ 一级意图 ──────────────┬ 二级（下钻） ──────────────────────┤
│ 性能 Performance        │ 功耗限制 / 频率 / 超频 / SMU 高级   │
│ 散热 Thermal            │ 温度墙 / 风扇模式 / 曲线编辑        │
│ 噪声 Noise              │ 目标转速 / 自动曲线 / dBA 估算      │
│ 灯效 Lighting           │ 颜色 / 亮度 / 效果                  │
│ 审计 Ledger  ← 签名物①  │ 写入记录 / 回读校验 / 回滚          │
│ 系统 System             │ 设置 / 驱动 / 关于                  │
└─────────────────────────┴────────────────────────────────────┘
```

- **模式不再是页面，是脊柱**（＝假设 B，**待确认**）：它决定下面所有页面的默认值与可调范围。
- **CPU / GPU / SMU 降为「性能」下的下钻分区**，不再是三个平行一级入口。
- **监测不再是一张页面，是常驻**：读数在每一页都可见（见 §5.2）。

### 4.3 每页层级序（统一三段）

1. **此刻状态**（一眼可读，不可交互）
2. **可改项**（受模式约束，展示"当前档位下的合法范围"）
3. **提交**（一次提交、一个确认、一条审计记录）

## 5. 签名物（已选定 ① + ②）

### 5.1 写入审计台 Write Ledger

**是什么**：每次写固件留一条**可回读**的记录——时间 / 目标 / 寄存器或方法 / 原值 / 新值 / 回读校验结果 / 结果。

**为什么它是签名物**：它不是设计出来的，是**从这个项目里长出来的**。项目已有写入闸门、`EcGuard`、300ms 同值去重、WMI 回显校验；审计台只是把已有工程从"看不见的护栏"变成"看得见的身份"。没有 AI 模板会产出它，也没有大厂控制台做它。

**顺带解决的既有缺陷**：§2.3 的「0 值可写」已由前端闸门兜住，审计台是同一问题的**完整解**（记录 + 回读 + 回滚）。

**待确认**：Server 侧需环形缓冲（建议上限 200 条，落盘）+ bridge 暴露只读查询。

### 5.2 仪器刻度条 Instrument Rail

**是什么**：温度 / 功耗 / 转速 / 噪声全站共用**同一套刻度语言**——统一零点、统一分档、统一阈值标记、统一 `tabular-nums`。

**为什么需要它**：截图证明单强调色不足以承担语义（GPU 温度蓝 / 图例绿）、进度条不携带刻度（0% 与 2% 不可区分）、不同页面量纲编码不一致。刻度条把这个"未决问题"变成一条**可复用的视觉语法**，而不是每页各判一次。

**副产品**：它天然成为「一眼可比」的驾驶舱基础，也是 §3 里大量空白版面的解药——内容不足时，刻度条本身提供结构。

## 6. 视觉层

保留：近黑哑光表面阶、石墨中性色、温度语义色、mono + `tabular-nums` 数值。

| 项 | 要求 |
|---|---|
| 发丝线 | 在非整数 DPI 下不得退化为彩色描边（改用 `box-shadow: inset 0 0 0 1px`，并在 125%/150%/200% 缩放下验证） |
| 字号阶 | 明确「读数 : 标签」的比值（当前 40px : 12px 跨度过大且无中间档） |
| 空态 | 定义"无数据 / 数据不足 / 读取失败"三种状态的视觉，**禁止把失败渲染成 0** |
| 图表 | ECharts 主题：坐标轴自适应数据范围、无霓虹、面积低透明、网格弱化 |
| 图标 | Lucide 线性，统一 1.75 描边（现状已基本一致，维持） |
| 应用标识 | 现状「八臂龙鳞」**已判定失败**：八个径向对称臂没有方向 → 读作齿轮/星芒；且用紫+蓝，正踩 DESIGN.md v2 禁区。候选见 `docs/logo-lab-2.html`（V1 实心鳞 / V2 负形核心 / V3 双鳞叠压 / V4 棱核），**暂缓**（2026-09-17 决定沿用原版；`logo-lab*.html` 留档待后续启用） |

## 7. 动效 / 交互层

docs/07 硬规则**全部继续有效**（读数瞬时、≤250ms、禁 `transition:all`、`:focus-visible`、reduced-motion 全局覆盖）。本轮新增：

| 场景 | 规则 |
|---|---|
| **模式切换** | 因为模式是脊柱，它必须是**全站最具辨识度的动效**：档位感（离散、有段落），不是渐变过渡 |
| **写入提交** | 待提交 → 提交中 → 已回读校验 / 失败可回滚；一次性反馈，不用 toast 单独承担 |
| **危险项** | 二次确认的**形态**与普通操作可区分（不是同款按钮换个颜色） |
| **读数** | 零过渡（继承） |
| **曲线拖拽** | 零过渡跟手（继承） |
| **装饰** | 零。删除一切无限 pulse / spin（加载态除外） |
